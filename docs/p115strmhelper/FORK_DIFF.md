# P115StrmHelper fork 与上游差异

本文记录 `ranzhigg/MoviePilot-Plugins` 当前维护的 P115StrmHelper 相对
`DDSRem-Dev/MoviePilot-Plugins` 的本地改动。只记录当前代码仍然存在的行为，
已删除的 Plex App 播放辅助链路不属于插件功能。

当前维护版本：

- V2：`2.8.112`
- V3：`3.0.8`

## 1. STRM 全量生成顺序

这是本 fork 最重要的行为差异，用于让 115、Plex 和 Infuse 的入库顺序保持一致。

V3 增加了两个显式配置：

- `full_sync_sync_mode=directory_tree`：按 115 目录树递归读取，使用目录修改时间和稳定的目录树顺序，不再把整个媒体库按文件时间打散后排序。
- `full_sync_generate_mode=ordered`：按 115 的旧入库内容到新入库内容顺序，由单个落盘 worker 顺序生成 STRM。

顺序模式下，较新的内容最后写入本地，因此获得最新的本地文件修改时间。Plex 或
Infuse 使用“日期已添加”倒序时，最新入库内容会排在前面，旧内容排在后面。

快速模式和并发生成模式仍然保留，用于速度优先的场景，但不承诺文件时间顺序：

```text
推荐：115目录树同步 + 严格有序生成
速度优先：快速兼容模式 + 并发生成（不保证顺序）
```

旧配置中的 `full_sync_order_by_user_ptime_desc` 会自动映射到上述两个新配置，升级
后不会悄悄退回无序并发生成。V3.0.7 同时将目录树枚举切换到可用的 iOS 接口，
避免继续依赖容易返回 405 的 web 接口。

## 2. 增量同步与目录树处理

- 全量、增量和生活事件同步都保留目录树比较，减少重复扫描和无效写入。
- 增量同步使用本地树、115 到本地映射树和 STRM 树进行比较，支持跳过路径缓存及二级目录扫描。
- 全量同步重复执行时尽量复用已有文件，不因为一次重扫就任意改写所有 STRM 的时间。
- 目录树导出失败会按受控次数重试，并在必要时降级存储，避免单次目录树异常直接中断整个任务。

## 3. 离线直存与重复任务

- 指定网盘路径的离线任务会进入持久化直存队列，下载完成后只扫描对应目标目录并生成 STRM，不必等待下一次全库扫描。
- 任务 hash 会持久化，MoviePilot 重载或容器重建后可以继续处理未完成任务。
- 115 返回“重复任务”时按幂等结果处理，区分新增、重复和真正失败，避免重复提交造成误报或重复入队。
- 直存任务失败使用退避重试，避免在 115 风控或任务尚未完成时高频请求。

## 4. 115 接口稳定性与并发控制

- 对高频端点增加冷却和时间预约，避免多线程同时唤醒造成请求突发。
- Open API 的 429 重试遵循 `Retry-After`，并受最大重试次数限制，不进行无限递归重试。
- 目录上传、离线轮询和相关 worker 在停止或异常后会清理运行状态，防止重载后残留“正在运行”状态。
- V2/V3 均保留针对 115 风控场景的失败即停、退避和日志提示；遇到风控时应等待冷却，不应连续触发全量任务。

## 5. 黑名单与失效文件清理

- STRM 生成黑名单使用 Aho-Corasick 自动机匹配关键词，覆盖全量、增量、API 和生活事件路径。
- 命中黑名单的广告文件可按本地配置从 115 云端删除；这是本 fork 的主动清理行为，使用前应审阅黑名单。
- 增量清理会跳过目录本身，避免把目录误计为文件删除；普通文件的媒体元数据清理仍受原配置控制。
- 分享 STRM 的清理、待确认删除和批量路径处理保留独立流程，不与全量同步混用。

## 6. STRM 播放链路

- STRM 播放使用 302 重定向直达 115 CDN，保留 WebDAV HEAD 能力、UA 隔离和受控缓存。
- 不再提供自定义媒体代理、能力令牌或 Plex App 媒体信息补全。
- 仓库已移除 `plex-mediainfo-helper`、V2 的 `helper/plex_app`、Plex App 前端组件、恢复脚本和对应文档；Plex 只负责扫描和播放插件生成的 STRM。

## 7. 通知与仓库范围

- 115 STRM 助手不再内置逐条通知；逐条通知由独立的 `StrmNotify` 插件负责，支持等待 NFO/封面、持久化去重和逐条发送。
- 当前 fork 只保留 `P115StrmHelper`（V2/V3）和 `StrmNotify`，其余历史插件、无关图标和维护脚本已经移除。
- 本地前端联邦组件与插件索引一起维护，配置中包含目录树同步、生成模式、媒体库刷新和风险提示。

## 8. 使用建议

1. 需要与 115 文件夹顺序一致时，使用“115 目录树同步 + 严格有序生成”。
2. 等全量 STRM 生成完成后再让 Plex 扫描媒体库，避免扫描到半成品时间顺序。
3. 平时优先使用增量同步和生活事件监控，只有目录树或本地库确实失步时才做全量。
4. 需要极限速度时可以切换快速/并发模式，但切换后不要把 Plex 或 Infuse 的日期顺序当作严格保证。
